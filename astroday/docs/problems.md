## Проверено и оставлено как есть (работает правильно)

- Платёж: сумма и тариф только с сервера; webhook перепроверяется запросом к YooKassa; сверяются статус, сумма, валюта, магазин, режим, заказ; один платёж = одна выдача (`FOR UPDATE`, `activated_at`); отменённый/неоплаченный — без доступа; закрытый браузер — сверка планировщиком; возвраты не трогают независимый доступ. (`e2e-buyer #7–9, #15`)
- Подпись Telegram Login / Mini App initData и срок её действия; чужой ID в запросе ничего не даёт. (`e2e-buyer #6`)
- Дедупликация и многочастная доставка покупателям; `retry_after`; неопределённый результат не повторяется.
- Тестерские сценарии `join_test`, повтор, контакт только свой, не сокращает оплаченный доступ. (`testers.test.mjs`)
- Движок: расхождение с независимым расчётом ≤0,035° по планетам и ≤0,006° по куспидам Placidus. (`engine-reference.test.mjs`)

## Осталось / ограничения

- Тестовый магазин YooKassa поддержан кодом (`YOOKASSA_TEST_*`), но по решению владельца проверка — реальной оплатой.
- Бесплатный превью-прогноз на сайте остаётся расчётным шаблоном (не OpenAI): запрос сайта ограничен 25 с.
- Лунные сутки и «Луна без курса», которые были в загруженных текстах тестеров, движком в рантайме не рассчитываются — в текстах покупателей их нет (не выдумываем).
- 18 одноразовых диагностических/импортных функций удалены из Railway 17.11 (часть импортов могла бы повторно запуститься при перезапуске платформы); осталось 8 сервисов, включая одну диагностическую функцию `astroday-join-test-readiness-check` (только чтение).
